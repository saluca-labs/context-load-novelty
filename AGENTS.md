# AGENTS.md

Instructions for AI coding agents working in this repository.

## What this is

The paper package behind a published preprint: the harness, raw per-idea logs, figures and paper
for a cross-family study of relevant context-load and LLM idea novelty. It is a research record,
not a library, and its scripts expect a staged directory layout before they run.

## Read in this order

1. `README.md`: the correction note, the "How it works" diagram, the Quickstart staging steps, and
   "Reproduce each result".
2. `paper.md`: what the study claims and how it measured it.
3. `code/analyze_isolation.py`, `code/analyze_frontier.py`, `code/make_figures.py`: the analysis
   that re-derives the results from `data/`.
4. `code/creativity_ratio.py`, `code/run_frontier.py`: how the logs were generated.
5. `human_rating/RATING_INSTRUCTIONS.md`: the blinded groundedness rubric.

## What you can and cannot see

- You can see every script, every released log, the figures, the paper and the rated sheet.
- You cannot see the `src` package that `code/smoke_local.py` and `code/run_confound.py` import,
  the confound study's step logs, or `_key.json` for the human rating. None of them is released.
- Analysis needs a local Ollama with `nomic-embed-text`. Generation also needs `gemma2:9b`, and
  the Claude scripts need the Claude CLI; their `CLAUDE = ...` path is the original author's
  machine and must be edited.

## The only numbers to trust

- Drift, divergence and groundedness per condition and per load: what `analyze_isolation.py` and
  `analyze_frontier.py` print from the staged `data/` logs (README Quickstart shows the
  2026-10-22 output).
- Cross-family gains (+49%, +96%, +147%, +109%): `figures/fig1_cross_family.png`, regenerated by
  `make_figures.py`.
- Human against judge groundedness (r = -0.12 and 0.00; means 0.45, 0.85, 0.77): the
  `grounded_human`, `grounded_strong` and `grounded` fields of
  `data/ideas_frontier_claude-fable-5.jsonl`.
- Citation: the concept DOI 10.5281/zenodo.21149156, never the version DOI.

## Quickstart

```bash
mkdir -p data/raw_logs_saluca/creativity/frontier saluca/paper/figures
cp data/ideas_*_isolation.jsonl data/raw_logs_saluca/creativity/
cp data/ideas_frontier_*.jsonl data/raw_logs_saluca/creativity/frontier/
python code/analyze_isolation.py
```

## Test

There is no test suite. The check that the analysis still reproduces the paper:

```bash
python code/analyze_isolation.py
python code/analyze_frontier.py
python code/make_figures.py
```

Passing looks like the isolation tables for the four models (gemma2:9b content drift 0.164
against plain 0.110), the frontier tables for gemma2-9b and claude-fable-5, and three figures in
`saluca/paper/figures/` that match `figures/`.

## Conventions

- Python 3, numpy, requests, matplotlib, openai. Do not add dependencies without a reason.
- No em-dashes in docs.
- If a script's read or write paths change, update the README diagrams and the script table in
  the same change.
- If a doc changes, regenerate `llms-full.txt` in the same change or delete it.

## Do not

- Edit `data/`, `figures/`, `human_rating/rate_me.csv`, `paper.md` or `paper.pdf`: they are the
  released record behind a published Zenodo preprint.
- Run `re_judge.py` or `merge_human_rating.py` against the staged logs and commit the result: both
  rewrite the logs in place.
- Commit the staged `data/raw_logs_saluca/` or `saluca/` directories.
- Run `deposit_zenodo.py`. It is the author's deposit tooling; deposits are made by the author.
- Commit secrets, hostnames, internal paths or personal emails.

## Done means

The three Test commands run from a staged clean clone and the README still matches what the code
on `main` does.
